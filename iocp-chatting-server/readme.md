# iocp-chatting-server
실시간 멀티 스레드 환경에서 **IOCP 기반 비동기 네트워크 서버 구조를 구현한 에코 채팅 서버**

## 주요 목표
- IOCP 기반 비동기 서버 구조 이해 및 구현
- 다중 클라이언트 동시 접속 및 처리
- 네트워크 레이어와 컨텐츠 레이어 분리
- 서버 내부 데이터 흐름 가시화

## 핵심 기능
- 다중 클라이언트 동시 접속
- Echo 패킷 처리
- 세션 기반 연결 관리

## 프로젝트 요약
- 객체지향 원칙을 적용하여 확장성과 유지 보수성이 높은 서버 아키텍처를 설계
- 네트워크 레이어와 컨텐츠 레이어를 논리적으로 분리하여 개발 생산성 향상
- Proxy 및 Stub 패턴 기반 패킷 코드 자동 생성기를 구현하여, 기능 추가 시 기존 코드 수정을 최소화하고 확장성을 확보

## 설계 포인트

### 기능 별 분리와 세션 중심의 네트워크 처리 구조
-  서버 기능을 역할 단위로 클래스화하여 추상화하였다. (Session, SessionManager, NetServer 등)
- `Session`은 소켓 핸들과 OVERLAPPED 구조체를 소유하며, 네트워크 I/O의 생명주기를 책임진다.
- 세션 내부에 다음과 같은 핵심 동작을 캡슐화하였다.
    - `SendPacket()` : 패킷 큐잉 및 `PostSend()` 호출
    - `PostSend()` : 동기화 처리 및 비동기 송신 요청
    - `OnRecv()` : IOCP 완료통지 수신시 호출되며 패킷 처리 흐름을 진행

### 네트워크 패킷 처리와 컨텐츠 로직의 분리
- 네트워크 레이어에서는 패킷 수신 및 파싱까지만 담당한다.
- 파싱된 패킷은 `PacketProcess`를 통해 메세지 타입을 판단한 후, 컨텐츠 레이어로 전달된다.
- `PacketProcess`는 컨텐츠 레이어 인터페이스에만 의존하며, 실제 게임 컨텐츠 및 비즈니스 로직은 네트워크 코드와 분리되어 실행되는것을 목표로 설계하였다.

### 인터페이스 기반 컨텐츠 실행 구조
- 컨텐츠 레이어는 공통 인터페이스를 통해 호출된다.
- `PacketProcess`는 인터페이스에만 의존하며,
  구체적인 컨텐츠 구현체에 대한 의존성을 가지지 않는다.
- 이 구조를 한 단계 더 추상화 하기 위해 `Packet Code Generator` 유틸을 구현해 적용하였다.
- 이를 통해 패킷 타입에 따른 디스패치 코드와 스텁 컨텐츠를 자동 생성하도록 하여, 향후 컨텐츠 추가 시 네트워크 및 패킷 처리 코드의 수정 없이 확장이 가능하도록 설계하였다.
